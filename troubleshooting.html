Top 25 Genesys Cloud troubleshooting APIs

API Console Genesys API Explorer

Ranked by where I’d start during a contact center incident. Pick the endpoint that fits the symptom, copy its path into the API Console, and replace any ID placeholders. For POST queries, add the JSON body in the console. Access depends on your token’s scopes, permissions, and division grants.

Troubleshooting endpoints

  1. Confirm the signed-in identity

    Access GET /api/v2/users/me

    Use first to verify which user the token represents.

  2. Confirm the organization

    Access GET /api/v2/organizations/me

    Check that your connection targets the expected Genesys Cloud organization.

  3. Find a failed or missing interaction

    Interactions POST /api/v2/analytics/conversations/details/query

    Query a narrow time window to recover the conversation ID and inspect participant and segment history.

  4. Trace a known interaction

    Interactions GET /api/v2/analytics/conversations/{conversationId}/details

    Inspect historical routing, disconnect types, segment timing and media metrics where available.

  5. Inspect an active interaction

    Interactions GET /api/v2/conversations/{conversationId}

    Check participant and communication state during a live incident.

  6. Check the current queue backlog

    Routing POST /api/v2/analytics/queues/observations/query

    Compare waiting, interacting and agent observations for affected queues.

  7. Inspect queue configuration

    Routing GET /api/v2/routing/queues/{queueId}

    Check routing settings, media settings and the in-queue flow reference.

  8. Check whether agents are joined

    Routing GET /api/v2/routing/queues/{queueId}/members

    Verify queue membership and each agent’s joined state.

  9. Check the agent’s routing status

    Agents GET /api/v2/users/{userId}/routingstatus

    Distinguish IDLE, INTERACTING, NOT_RESPONDING and OFF_QUEUE when investigating missed offers.

  10. Check the agent’s presence

    Agents GET /api/v2/users/{userId}/presences/purecloud

    Compare their current Genesys Cloud presence with their ACD routing status.

  11. Check the agent’s selected station

    Telephony GET /api/v2/users/{userId}/station

    Confirm station association when an agent cannot place or receive calls.

  12. Find the affected SIP trunk

    Telephony GET /api/v2/telephony/providers/edges/trunks

    Inventory trunks and identify the trunk ID for the affected voice path.

  13. Inspect SIP trunk metrics

    Telephony GET /api/v2/telephony/providers/edges/trunks/{trunkId}/metrics

    Check available trunk metrics while investigating carrier or call-capacity issues.

  14. Check Edge availability

    Telephony GET /api/v2/telephony/providers/edges

    Inventory Edges and inspect current status for deployments that expose them.

  15. Inspect Edge metrics

    Telephony GET /api/v2/telephony/providers/edges/{edgeId}/metrics

    Check reported health metrics for the Edge involved in a voice incident.

  16. Verify phone configuration

    Telephony GET /api/v2/telephony/providers/edges/phones/{phoneId}

    Check the phone definition and site association when an endpoint fails.

  17. Check the inbound call route

    Routing GET /api/v2/architect/ivrs/{ivrId}

    Verify schedule and flow references for the inbound number.

  18. Confirm the Architect flow

    Routing GET /api/v2/flows/{flowId}

    Check flow type and published-version information when callers hit an unexpected path.

  19. Investigate after-hours misrouting

    Routing GET /api/v2/architect/schedulegroups/{scheduleGroupId}

    Check time zone and open, closed and holiday schedule associations.

  20. Measure the incident’s impact

    Analytics POST /api/v2/analytics/conversations/aggregates/query

    Compare call volume, abandons and wait time across queues and time buckets.

  21. Reconstruct an agent’s timeline

    Analytics POST /api/v2/analytics/users/details/query

    Inspect historical presence and routing status across the incident window.

  22. Investigate missing access

    Access GET /api/v2/authorization/subjects/{subjectId}

    Review role and division grants for an affected authorization subject.

  23. Inspect a failing data action

    Integrations GET /api/v2/integrations/actions/{actionId}

    Confirm the action’s published definition and associated integration.

  24. Find configuration changes near the incident

    Audit POST /api/v2/audits/query

    Start an audit query for the relevant service and time window to identify changes and actors.

  25. Read completed audit results

    Audit GET /api/v2/audits/query/{transactionId}/results

    Retrieve audit records using the transaction ID after the query completes.

Example query bodies

#3 and #21 · Search a 15-minute incident window

Replace the UTC timestamps with your incident window. The example returns the first page.

{
  "interval": "2026-11-19T07:00:00Z/2026-11-19T07:15:00Z",
  "paging": { "pageSize": 25, "pageNumber": 1 }
}
#6 · Check a single queue’s backlog

Replace QUEUE_ID with the affected queue’s ID.

{
  "filter": {
    "type": "or",
    "predicates": [
      { "dimension": "queueId", "value": "QUEUE_ID" }
    ]
  },
  "metrics": ["oWaiting", "oInteracting"]
}
#24 and #25 · Run and retrieve an audit query

Use the transactionId returned by #24 to check progress at GET /api/v2/audits/query/{transactionId}. When the query completes, use #25 for the records.

Endpoint methods and paths checked against the Genesys Cloud Python SDK 269.0.0.
